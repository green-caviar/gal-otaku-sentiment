# レポート：オタク・ギャル風の投稿のポジ／ネガ判定

自然言語処理 第2回 演習「ポジ／ネガ判定を2つのアプローチで」のレポート。オタク・ギャル風の SNS 投稿を、ルール（単語リスト）と LLM で判定して比べる。LLM は、課題の zero-shot に加えて、自分で考えた「ペルソナ推論」のプロンプトでも判定した。

## タスク定義

- 入力：オタク・ギャル風の SNS 投稿1件（短文）
- 出力：pos（ポジティブ）／neg（ネガティブ）の2値
- ラベルの基準：使われている語の辞書的な意味ではなく、書き手の本当の気持ちで付ける。
  例：「まじ尊すぎて死ぬ」は「死ぬ」を含むが、推しへの感動なので pos。
- 迷う投稿：同じ語が文脈で逆の意味になるもの（11・12 の「キャパい」）。
  何に対する気持ちか（推しか、自分の寝坊か）で判断した。

## データ

`data/labeled_data.csv`（12件、pos 6件・neg 6件）。投稿はすべて自分で書き、正解ラベルも自分で付けた。公開データは使っていない。

| 型 | 件数 | id |
|---|---|---|
| 否定語なのにポジ | 3 | 1, 4, 5 |
| 素直なポジ | 2 | 7, 8 |
| 素直なネガ | 3 | 2, 3, 6 |
| 皮肉（ポジ語なのにネガ） | 2 | 9, 10 |
| 迷う投稿（同じ「キャパい」で逆） | 2 | 11, 12 |

- 型を考えるときに、生成AI（Claude）が出したギャル語・オタク語の例文を参考にした。データの文は、それを見て自分の言葉で書き直したもの。
- 4「逆に会いたくないまであるわー」は、会う頻度が多すぎるほど仲の良い友達への好意として pos にした。5「こいついつも誕プレくれるんだけど笑まじだりー」は、いつもプレゼントをくれる相手への照れ隠しとして pos にした。どちらも、根拠は本文に書かれていない。

## 手法

### ルール（単語リスト）

`src/run.py`。語の辞書的な意味で、ポジの語とネガの語のリストを作った。ネガの語の数がポジの語の数より多ければ neg、それ以外（同数・どちらも0件）は pos とする。

- ポジ：最高、好き、推す、尊、美し、盛れ、あげ、優勝、さすが
- ネガ：死ぬ、だりー、だるい、きも、悪すぎ、長すぎ、えぐい、キャパい、会いたくない、無理

リストはデータを見ながら作ったので、ルールに有利な面がある。

### LLM zero-shot

`prompts/zeroshot.txt`。正解例を添えず、判定の基準だけを伝える。

```text
次の投稿を書いた人の本当の気持ちがポジティブかネガティブか、
「ポジ」か「ネガ」で答えてください。
使われている語の表面ではなく、書き手の本当の気持ちで判定してください。
投稿：{text}
```

### LLM ペルソナ推論（自分で考えた手法）

`prompts/persona.txt`。投稿だけで判断させず、推論の手順を指示する。

1. ペルソナ：投稿を書きそうな人物像（年代、界隈、場面）を推測する。
2. 言葉づかい：その界隈での用語や言い回しの意味を挙げる。
3. 迷う場合：投稿からは分からないが推測できる文脈を2つ以上考え、それぞれの妥当さを評価し、最も妥当な文脈から結論を出す。
4. 結論：「ポジ」か「ネガ」で答える。

ねらいは、語の表面ではなく「誰が、どんな場面で書いたか」から気持ちを推し量らせることにある。どの投稿が迷う投稿かは LLM に教えず、迷うかどうかも LLM に判断させた（教えると答えのヒントになるため）。

## 設定

- LLM：Claude Sonnet 5.5（`claude-sonnet-5-5`）。Claude Code のサブエージェントとして実行した。正解ラベルは渡していない。ツールとウェブ検索は使わせていない（手順2の「言葉づかい」は、LLM が持つ知識の範囲で答えさせた）。
- 日付：2026-11-16
- 聞き方：12件を1回にまとめて聞いた。
- 回数：LLM の答えは回によって変わりうるので、各手法を5回ずつ実行し、正解数の平均をとった。毎回、新しいエージェントに同じプロンプトを渡した。温度などの生成の設定は指定できず、既定の設定のまま。
- 追加の比較：4 を単独で聞いたものと、末尾に「笑」を付けたものを、zero-shot で1回ずつ聞いた（`outputs/extra/post4_wara.csv`）。
- Python 3.15.0、標準ライブラリだけ。

## 考察

ルールは語の表面で誤り、LLM は文脈から多くを補えた。ペルソナ推論は zero-shot を平均で上回った。ただし、本文に書かれていない前提で正解が決まる投稿（4・5）は、どの手法でも安定して当てられなかった。

### ルールの誤り：10「サイト待ち時間長すぎ笑　さすが運営、期待を裏切らないな－」

「さすが」をポジ、「長すぎ」をネガとして拾い、数が同じになって既定値の pos に落ちた。皮肉は、語の向きと書き手の気持ちが逆になるので、単語リストでは捉えにくい。LLM は2手法とも5回すべて neg と判定でき、「悪い意味で期待どおり」という皮肉として読めていた。

また、ルールが当たった 1・7・11 も、ポジの語とネガの語が同数で既定値の pos に落ちただけで、既定値を neg にすれば3件とも外れる。正解数だけでは、ルールがどこまで分かっているかは測れない。

### LLM の誤り：5「こいついつも誕プレくれるんだけど笑まじだりー」

zero-shot は5回とも neg だった。ペルソナ推論は、4回で「照れ隠しで実は嬉しい」と「本当に面倒」の2つの文脈を比べ、そのうち3回は「本当に面倒」を選んで neg にした。残りの1回は文脈を比べずに「だりーが本心」として neg にした。pos にしたのは、「毎回くれるという好意的な事実」と「笑」を根拠に照れ隠しを選んだ1回（3回目）だけだった。

この投稿の正解は、「こいつ」が誰かで変わる。好きな友達なら照れ隠しで pos だが、たとえばバイト先の嫌いな店長から毎回もらうのであれば、本当に面倒で neg になる。どちらの前提も投稿には書かれておらず、どちらも十分ありうる。このように、書かれていること以外に判断の条件があり、条件しだいで pos も neg も妥当になる投稿は、LLM でも人でも判定が難しい。ペルソナ推論の答えが回によって割れたことも、どちらの文脈も妥当であることを表していると考える。

4 も同じ構造である。ペルソナ推論は5回中4回 pos と当てたが、pos にした4回とも、選んだ文脈は「推しが好きすぎて会うのが怖い」で、自分の意図（会う頻度が多すぎるほど仲の良い友達）とは違った。ラベルは当たっても、根拠は当たっていない。また、zero-shot で末尾に「笑」を付けても neg のままだったので、手がかりを1つ足すだけでは前提の不足は補えなかった。

これらは LLM の能力不足というより、入力を投稿1件に限ったタスク定義の限界である。気持ちを決めるのに必要な情報（相手との関係）が入力にない以上、どう工夫しても出力は定まらない（第2回 p.7）。改善するなら、投稿者の過去の投稿や相手との関係を入力に加えるか、「文脈なしでは判定できない」を3つ目のラベルとして認める必要がある。

### 2つの LLM 手法の違い

zero-shot は5回とも完全に同じ答えで、安定していた。迷う手順がないため、語の表面に沿って毎回同じ結論を出したと考えられる。ペルソナ推論は平均で1件多く当てたが、正解数は10〜12で揺れた。文脈を複数考えて選ぶ手順のため、どの文脈を妥当とするかが回によって変わる。迷う投稿で別の読みを試せる強みと、結果が安定しない弱みは、同じ手順から来ている。

### どちらの誤りが痛いか

用途によって変わる。運営への苦情を拾いたいなら、皮肉のネガを pos と見落とすルールの誤り（10）が痛い。推しや友達への好意を集めたいなら、照れ隠しを neg とする LLM の誤り（4・5）が痛い。

### 限界

データは12件と少なく、正解ラベルは自分1人で付けた。ルールの単語リストはデータを見て作った。LLM は1つのモデルだけで、各手法5回しか実行していない。

## 生成AIの利用申告

- **Claude Code（Claude Opus 5.5）**：課題条件の整理、リポジトリの構成と `src/run.py` の作成・動作確認、単語リスト・タスク定義・考察・このレポートの文の下書きに使った。内容は自分で確認し、ラベル、判断理由、ペルソナ推論の手法の考え方、5 についての考察は自分で決めた。
- **Claude（チャット）**：ギャル語・オタク語の例文を出させ、データの型を考える参考にした。データの文は自分で書いた。
- **Claude Sonnet 5.5**：手法として、投稿のポジ／ネガ判定に使った（「設定」を参照）。
