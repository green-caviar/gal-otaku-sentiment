# オタク・ギャル風の投稿のポジ／ネガ判定：ルールと LLM の比較

自然言語処理 第2回 演習レポート（リポジトリ gal-otaku-sentiment、詳しい記録は docs/details.md）

SNS では、特定のペルソナの間でしか伝わらない言葉づかいがよく見られる。たとえば「尊すぎて死ぬ」は、推しへの最大級の賛辞である。本演習では、こうした特有の言葉づかいを LLM が推論して、ポジ／ネガを判定できるかを確かめたかった。そこで、語の表面と気持ちがずれる投稿を使って、ルールと LLM の差を比べた。さらに、単語の意味や正解例を教えるのではなく、「相手の立場を推論する」という多くの場面で応用できる姿勢そのものを伝えるプロンプト（以下、ペルソナ推論）で、判定が改善するかを試した。

タスクは、オタク・ギャル風の SNS 投稿1件を入力とし、pos／neg の2値を出力とする分類とした。正解ラベルは、語の辞書的な意味ではなく、書き手の本当の気持ちで付けた。データは自作の投稿12件（pos 6件・neg 6件）で、正解ラベルも自分で付けた。内訳は、否定語なのにポジ3件、素直なポジ2件、素直なネガ3件、皮肉（ポジ語なのにネガ）2件、同じ語が文脈で逆になる迷う投稿2件である。迷う投稿は、「推しが美しすぎてキャパい」を pos、「起きたら10時でキャパい笑」を neg とし、何に対する気持ちかで判断した。

手法は3つ比べた。ルールは、辞書的な意味でポジ語9語とネガ語10語のリストを作り、ネガ語の数が多ければ neg、それ以外は pos とした。LLM zero-shot は、「語の表面ではなく、書き手の本当の気持ちで判定して」と指示し、「ポジ」か「ネガ」で答えさせた。ペルソナ推論は自分で考えた手法で、特定の界隈の知識ではなく、相手の立場を推論する手順を伝える。具体的には、書き手の人物像を推測し、その界隈での言葉の意味を挙げ、迷うときは推測できる文脈を2つ以上考えて最も妥当なものから結論を出させた。LLM は Claude Sonnet 5.5 を使い（2026年11月16日）、12件をまとめて聞いた。正解ラベルは渡していない。答えが回によって変わりうるので、LLM の2手法はそれぞれ新しいエージェントで5回ずつ実行し、正解数の平均をとった。

結果を表1に示す。ルールは12件中7件、zero-shot は5回とも10件、ペルソナ推論は平均11.0件（10〜12件）正解した。LLM の2手法で差が出たのは2件だけで、ほかの10件はどちらも5回すべて正解した。差が出たのは、投稿4「逆に会いたくないまであるわー」（正解は pos、zero-shot 0/5、ペルソナ推論 4/5）と、投稿5「こいついつも誕プレくれるんだけど笑まじだりー」（正解は pos、zero-shot 0/5、ペルソナ推論 1/5）である。

表1　手法ごとの正解数（12件中）

| 手法 | 正解数 |
|---|---|
| ルール | 7 |
| LLM zero-shot（5回の平均） | 10.0 |
| LLM ペルソナ推論（5回の平均） | 11.0 |

ルールの誤りとして、投稿10「サイト待ち時間長すぎ笑　さすが運営、期待を裏切らないな－」を取り上げる。ルールは「さすが」をポジ、「長すぎ」をネガとして拾って同数になり、既定値の pos に落ちた。皮肉は語の向きと気持ちが逆になるので、単語リストでは捉えにくい。一方、LLM は2手法とも5回すべて neg と判定でき、皮肉として読めていた。

LLM の誤りとして、投稿5を取り上げる。zero-shot は5回とも neg と判定した。ペルソナ推論も、「照れ隠し」と「本当に面倒」の2つの文脈を比べて、多くの回で「本当に面倒」を選んだ。この投稿の正解は、「こいつ」が誰かで変わる。好きな友達なら照れ隠しで pos だが、バイト先の嫌いな店長から毎回もらうのであれば neg になる。このように、書かれていること以外に判断の条件があり、条件しだいで pos も neg も妥当になる投稿は、LLM でも人でも判定が難しい。投稿4も同じ構造で、ペルソナ推論は4回当てたが、当てた4回とも選んだ文脈は「推しに会うのが怖い」であり、自分の意図（会う頻度が多すぎるほど仲の良い友達）とは違った。気持ちを決める情報が入力にない以上、これは LLM の能力よりも、入力を投稿1件に限ったタスク定義の限界だと考える。

2つの LLM 手法を比べると、ペルソナ推論は「尊すぎて死ぬ」のような界隈の言葉づかいを説明したうえで判定でき、平均で1件多く当てた。相手の立場を推論する姿勢を伝えることには、一定の効果があったと言える。ただし、どの文脈を選ぶかが回によって変わるので結果が揺れ、推論の過程を書かせる分、時間は zero-shot の約11倍（約25秒と約2秒）かかった。

生成AIは次のように使った。Claude Code（Claude Opus 5.5）は、課題条件の整理、リポジトリの構成とコードの作成・動作確認、単語リストとレポートの文の下書きに使った。ラベル、判断理由、手法の考え方、考察の主張は自分で決め、内容を確認した。Claude（チャット）には、ギャル語・オタク語の例文を出させてデータの型を考える参考にしたが、データの文は自分で書いた。Claude Sonnet 5.5 は、手法として投稿のポジ／ネガ判定に使った。
