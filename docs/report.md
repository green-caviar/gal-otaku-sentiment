# オタク・ギャル風の投稿のポジ／ネガ判定：ルールと LLM の比較

自然言語処理 第2回 演習レポート。リポジトリ：gal-otaku-sentiment（詳しい記録は `docs/details.md`）

## 1. 目的・動機

SNS では、特定のペルソナの間でしか伝わらない言葉づかいがよく見られる（例：「尊すぎて死ぬ」は推しへの最大級の賛辞）。こうした特有の言葉づかいを LLM が推論して、ポジ／ネガを判定できるかを確かめたかった。そこで、語の表面と気持ちがずれる投稿で、ルールと LLM の差を比べた。さらに、単語の意味や正解例を教えるのではなく、「相手の立場を推論する」という多くの場面で応用できる姿勢そのものを伝えるプロンプト（ペルソナ推論）で、判定が改善するかを試した。

## 2. タスク定義

- 入力：オタク・ギャル風の SNS 投稿1件。出力：pos／neg の2値。
- ラベルの基準：語の辞書的な意味ではなく、書き手の本当の気持ちで付ける。
- 迷う投稿：同じ語が文脈で逆になるもの（「推しが美しすぎてキャパい」は pos、「起きたら10時でキャパい笑」は neg）。

## 3. データ

自作の投稿12件（pos 6・neg 6）。正解ラベルも自分で付けた（`data/labeled_data.csv`）。内訳は、否定語なのにポジ3、素直なポジ2、素直なネガ3、皮肉（ポジ語なのにネガ）2、迷う投稿2。

## 4. 手法・設定

- **ルール**：辞書的な意味でポジ語9語・ネガ語10語のリストを作り、ネガ語の数が多ければ neg、それ以外は pos。
- **LLM zero-shot**：「語の表面ではなく、書き手の本当の気持ちで判定して」と指示し、「ポジ」か「ネガ」で答えさせる。
- **LLM ペルソナ推論**（自分で考えた手法）：特定の界隈の知識ではなく、相手の立場を推論する手順を伝える。①書き手の人物像を推測する、②その界隈での言葉の意味を挙げる、③迷うときは推測できる文脈を2つ以上考え、最も妥当なものから結論を出す、④ポジかネガで答える。
- LLM は Claude Sonnet 5.5（2026-11-16）。12件をまとめて聞き、正解ラベルは渡していない。答えが揺れるので、各手法を新しいエージェントで5回ずつ実行して平均した。

## 5. 結果

| 手法 | 正解数（12件中） |
|---|---|
| ルール | 7 |
| LLM zero-shot（5回の平均） | 10.0（5回とも10） |
| LLM ペルソナ推論（5回の平均） | 11.0（10〜12） |

LLM の2手法で差が出たのは次の2件だけで、ほかの10件はどちらも5回すべて正解した。

| 投稿 | 正解 | zero-shot | ペルソナ推論 |
|---|---|---|---|
| 4 逆に会いたくないまであるわー | pos | 0/5 | 4/5 |
| 5 こいついつも誕プレくれるんだけど笑まじだりー | pos | 0/5 | 1/5 |

## 6. 考察

**ルールの誤り（10「サイト待ち時間長すぎ笑　さすが運営、期待を裏切らないな－」）**：「さすが」をポジ、「長すぎ」をネガとして拾って同数になり、既定値の pos に落ちた。皮肉は語の向きと気持ちが逆なので、単語リストでは捉えにくい。LLM は2手法とも5回すべて neg と判定できた。

**LLM の誤り（5「こいついつも誕プレくれるんだけど笑まじだりー」）**：zero-shot は5回とも neg だった。ペルソナ推論も、「照れ隠し」と「本当に面倒」の2つの文脈を比べて、多くの回で「本当に面倒」を選んだ。この投稿の正解は「こいつ」が誰かで変わる。好きな友達なら照れ隠しで pos だが、バイト先の嫌いな店長から毎回もらうのであれば neg になる。このように、書かれていること以外に判断の条件があり、条件しだいで pos も neg も妥当になる投稿は、LLM でも人でも判定が難しい。4 も同じで、ペルソナ推論は4回当てたが、当てた4回とも選んだ文脈は「推しに会うのが怖い」で、自分の意図（会う頻度が多すぎるほど仲の良い友達）とは違った。気持ちを決める情報が入力にない以上、これは LLM の能力より、入力を投稿1件に限ったタスク定義の限界だと考える。

**2つの LLM 手法の違い**：ペルソナ推論は「尊すぎて死ぬ」のような界隈の言葉づかいを説明したうえで判定でき、平均で1件多く当てた。一方で、どの文脈を選ぶかが回によって変わるので結果が揺れ、推論の過程を書かせる分、時間は zero-shot の約11倍（約25秒と約2秒）かかった。

## 7. 生成AIの利用申告

- Claude Code（Claude Opus 5.5）：課題条件の整理、リポジトリの構成とコードの作成・動作確認、単語リスト・レポートの文の下書き。ラベル、判断理由、手法の考え方、考察の主張は自分で決め、内容を確認した。
- Claude（チャット）：ギャル語・オタク語の例文を出させ、データの型を考える参考にした。データの文は自分で書いた。
- Claude Sonnet 5.5：手法として、投稿のポジ／ネガ判定に使った。
